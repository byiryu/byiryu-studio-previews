모드 1 명세 (마이페이지 기본 앵커 설정)

  • auto (디폴트) — 자동 룰 4-way (체감 ≤ 5°C → outer / ≥ 25°C → top / 비·눈 → shoes / 기본 → bottom). v1.0 과 동일 마찰 0
  • ask — 메인 진입 시 모드 2 강제 진입 (옵션 X 한 사용자만 선택). 마찰 인지 후 능동 선택
  • 저장 위치 — server `weather_outfit_users.default_anchor_mode` enum ('auto'|'ask'). 클라 변경 시 즉시 fire-and-forget POST
  • 설명 문구 — 각 옵션 하단 작은 설명 (마찰 차이 명시)
마이페이지 신규 v1.1 — 2 항목 ★ 기본 앵커 · ★ 다른 옷 기준 (deeplink)

1. 모드 3 (디폴트, 99% 흐름)

  1. 앵커 카드 시각 강조가 한눈에 식별 가능한가? (배지 📌 + 보더 + 배경) — 다른 카드와 구분이 명확
  2. 헤더 캡션 "📌 오늘은 연청 청바지 기준" — 색 톤 + 의류명 + 안내가 자연 한 문장
  3. 앵커 카드 외 3 카드의 색이 앵커 색과 조화 인가? — denim blue ↔ 베이지 니트 ↔ 카멜 트렌치 ↔ 화이트 스니커즈 매칭 정합

2. 모드 2 진입점 (2 곳)

  1. 헤더 우측 "▼ 다른 옷 기준" 버튼이 저마찰 인지? (작아서 무시 가능 + 의도 시 식별 가능 — 균형)
  2. 마이페이지 신규 2 항목 위치 (NEW 배지) 가 자연 — 다른 설정 항목과 톤 정합
  3. ★ 모드 3 앵커 카드 탭이 진입점 X = 정보·액션 분리 인식이 명확한가? (시각적으로 "이건 탭 X" 신호 — 보더만 + 인터랙티브 cue X)

3. 모드 2 3-단계 화면

  1. 3 단계가 한 화면 위→아래 = 흐름이 자연? (이전/다음 navigation 없이 스크롤 = OK)
  2. [1] → [2] → [3] 의미 연결 — 카테고리 선택 → 의류 그리드 동적 갱신 → 색 톤 그리드 헤더 = 의류명
  3. 색 톤 그리드의 hex 시각 시그니처 = 사용자가 "이게 연청이구나" 식별 가능 (140 hex sanity PASS 정합)
  4. "추천에 맡김" 디폴트 옵션이 명확 — hatched 패턴 + label "추천에 맡김" + "디폴트" 표기
  5. CTA "이걸로 추천 받기" 문구가 자연 (한국어 톤)

4. 마이페이지 + 모드 1

  1. 기본 앵커 설정 (auto/ask) 의미가 명확 — 각 옵션 하단 작은 설명이 충분
  2. '매번 묻기' 선택 시 마찰 인지 — 설명 문구 "메인 진입 때마다 의류·색 톤 선택 화면이 떠요" 명확

5. 엣지 케이스 4 종

  1. 사전 차단 (anchor_eligible=false / gender_lock) 처리 자연 — 빈 배열 → 옵션 비노출 = 마찰 0
  2. server 안전망 (auto-partial / fallback_used / INVALID_ANCHOR 400) 의 사용자 UX 영향 0 (silent 또는 자연 결과)
PASS 시 다음: wireframes.md 정합 갱신 (cross-plat 단일 명세, 본 페이지 시각 + 명세 본문 흡수) → PLAN aos M7 step-8 / ios M7 step-7 의 wireframes deferral 해소 → 본격 UI 코딩 진입 (server step-4~12 + aos step-2~7 + ios step-3~10)

FAIL / 의견: 의류·색·문구·진입점 위치·NEW 배지·엣지 처리 등 구체 변경 의견 → 본 HTML 갱신 + wireframes.md 정합 (사이클)

★ V_anchor_ux sanity 사이클 (spec §10.6 + §10.9 V_anchor_sanity 정합): 시각 검토 → 의견 반영 → 재검토 PASS → wireframes.md 정합 갱신 → UI 코딩 진입.
