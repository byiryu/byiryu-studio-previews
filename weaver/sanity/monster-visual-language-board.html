몬스터 비주얼 언어 룰

M2 step-2 몬스터 에셋 생성 전 선행 결정. "정답=퍼즐(라벨 X)" 과 "본체 4색 회피" 충돌을 어떻게 양립시킬지 — 어느 시각 채널이 정답 단서를 운반하는가를 확정한다.

🛡 매체 게이트 #8 — 이 보드 = 비주얼 언어 *룰*(시스템·가독성) 검증. 아래 도형은 "어느 채널이 단서를 나르나"를 보여주는 룰 도식이지 최종 몬스터 아트가 아니다. 실제 크리처 appeal·깊이·림라이트·픽셀 craft = PixelLab 생성으로 판정 (룰 확정 후). 도형의 밋밋함 ≠ 결과물 품질.

1 충돌 — 두 원칙이 부딪힌다

spec §2.6 — 퍼즐
정답 무기를 라벨로 안 알려줌. 몬스터 생김새가 학습 단서 → 배워서 읽는다(운 X).
∴ 생김새가 solvableBy 를 *말해야* 한다
⚔
asset-manifest — 색=정보
카테고리 4색은 무기·VFX 전용. 본체·몬스터 몸체는 4색 회피 (트랙 위 색 가독 보호).
∴ 몬스터 몸을 통째 카테고리색으로 칠할 수 없다

2 양립안 — 본체는 중립, 단서는 채널 4개로

몸 전체를 색칠하지 않고도 정답을 읽히게 한다. 본체 = 중립 다크(void fauna) 위에 단서 채널 4개를 얹는다. 색은 작은 코어/액센트에만 — 4색 회피 원칙(몸)과 색=정보(코어) 둘 다 성립.

1순위 단서

① 카테고리색 코어 / 액센트

몸은 중립, 눈·코어·관절 글로우만 카테고리색. = "이 코어색 = 이 무기-드론". 무기-드론과 같은 DNA(다크 셸 + 색 코어)라 "같은 색끼리 매칭" 직관.

보강

② 실루엣 클래스

카테고리별 형태 언어 — 색맹·원거리·저대비에서도 구분. 둥근 부유체(일반) / 각진 장갑 덩어리(장갑) / 낙하 파편(요격) / 가로 게이트(베리어).

보강

③ 출현 위치 · 방향

등장 앵커가 단서 — 낙하물=천장에서↓ / 장갑=정면 접근 / 베리어=전폭. "어디서 오나"가 "무엇이냐"를 예고(텔레그래프 거리 = spec §2.6).

장갑 전용

④ hits2 텔레그래프

2히트 장갑 = 굵은 2중 외곽 + 플레이트 분할 (데미지 X — "튼튼해 보임"이 곧 2히트 신호). 1히트 일반과 한눈에 구분.

5 퍼즐이 안전한 이유 (§2.6 — 3장치)

① 충돌 예산(하트 N)처음 본 몬스터 못 잡아도 즉사 X — 하트 1만 깎이고 배운다.
② 반복 등장배운 비주얼 언어를 다음에 적용 → 마스터리.
③ 일관된 룰코어색·실루엣·방향이 *항상* 같은 의미 → 학습 가능(운 X).

✓ 결정 항목

  1. 양립안 채택? — 본체 중립 + 코어색/실루엣/방향 단서 (몸 4색 회피 유지). ← 권장
  2. 단서 1순위 = 카테고리색 코어 로 충분한가, 아니면 실루엣 클래스도 카테고리별로 강하게 못박을까? (권장: 코어색 1순위 + 실루엣은 "유형"(부유/장갑/낙하/게이트) 구분에만 — 색이 정답, 실루엣은 보강. 색맹 대비는 ②+③가 커버)
  3. 장갑 hits2 텔레그래프 = 굵은 2중 외곽 / 플레이트 분할 / 둘 다(권장)?
  4. 본체 중립색 = 다크 슬레이트 + 림라이트 방향 OK? (⚪ 흰색·4색·bg 와 분리 + 다크 트랙 가독 — PixelLab 프롬프트 불변 제약으로 박음)
