몬스터 비주얼 언어 룰 — 본체 ⊥ 단서 분리

M2 step-2 몬스터 에셋 생성 전 선행 결정. 정답(solvableBy)은 집합(1~N) — 한 몬스터가 여러 무기로 잡힐 수 있다. ∴ 색을 본체에 굽지 않고 본체(중립) ⊥ 단서(틴트 레이어) 로 분리한다.

🛡 매체 게이트 #8 — 이 보드 = 단서 *시스템·가독 문법* 검증. 도형은 "단서가 어떻게 켜지나"를 보여주는 룰 도식이지 최종 몬스터 아트가 아니다. 크리처 appeal·craft = PixelLab 생성으로 판정(룰 확정 후). 본체 도형의 밋밋함 ≠ 결과물.

1 충돌 — 두 원칙 + 정답은 집합

spec §2.6 — 퍼즐 + 집합
정답 무기를 라벨로 안 알려줌 · solvableBy = 집합(1=엄격 / N=유연). 생김새가 단서.
∴ 한 몬스터가 🔵 또는 🔴… 여러 정답을 가질 수 있다
⚔
asset-manifest — 색=정보 · 재사용
4색 = 무기·VFX 전용 · 본체 4색 회피 · 스프라이트 3~4종 재사용(아트 ≠ 13).
∴ 색을 본체에 구우면 조합 폭발(최대 15) + 재사용 붕괴

2 해법 — 본체와 단서를 분리한다

색을 본체에 굽는 대신, 중립 본체 스프라이트(아키타입만) 위에 단서 레이어(런타임 틴트) 를 얹는다. 캐릭터·드론의 "흰 마스터 → 런타임 스킨 틴트" 패턴을 그대로 재적용 — 본체 스프라이트는 solvableBy를 모른다.

🪨 본체 레이어 디자인 · PixelLab

중립 void fauna 스프라이트. 아키타입(부유/장갑/낙하/게이트) + hits(장갑) 만 인코딩. 카테고리 4색·solvableBy 안 박음.

∴ 본체 종류 = 아키타입 3~4개뿐 (조합 폭발 0). 다크 셸+림라이트로 다크 트랙 가독.

💠 단서 레이어 디자인 룰 + 런타임 조립

solvableBy 집합을 카테고리색 단서 요소 1~N개로 표시(런타임 틴트·배치). 틴트 마스터 1장(흰 코어) 재사용.

∴ 다중 정답 = 데이터로 무한 조합. {🔵} {🔵🔴} {🔵🔴🟡}… 모두 같은 본체 + 단서 N개.

역할디자인 영역 — "무엇을 그리나"Unity 런타임 — "어떤 조합으로 켜나"
본체중립 스프라이트(아키타입×hits, 4색·정답 무관)—
단서단서 요소 룩(틴트 마스터) · 다중 표시 문법 · 경고 링 다색 룰 · 위치solvableBy 집합 읽어 N개 인스턴스화·틴트·배치 · hits/behavior/telegraph

분리의 대가로 생긴 새 디자인 숙제. 빠른 플레이 중 "이건 🔵, 저건 🔵+🔴" 가 0.x초에 읽혀야 한다. 세 후보 — 각 1개 / 2개 / 3개 정답 표시:

4 단서 채널 정리 (분리 모델 반영)

정답(solvableBy)은 ① 가 단독 운반 · 나머지는 아키타입·가독 보강.

채널운반 정보소속
① 단서 레이어 (코어/핍, 틴트)solvableBy 집합 1~N — 유일한 정답 신호디자인 룩 + 런타임 조립
② 실루엣 클래스아키타입(부유/장갑/낙하/게이트) — 정답 아님, 위협 유형디자인 본체
③ 출현 위치·방향천장↓ / 정면 / 전폭 — 텔레그래프(언제·어디서)런타임 배치(ChunkDef)
④ hits2 장갑 텔레그래프굵은 2중 외곽 + 플레이트 = 2히트(데미지 X)디자인 본체
