트랙 줄무늬 누적색 팔레트

트랙면 rev.3 = 흰색 고정 + 누적색(accent) 스테이지별 순환(Accents[idx%N] — 코드 구현됨). 흐름 매핑 = 순환 확정(2026-06-21 인터뷰). 남은 건 팔레트 색값·개수 — 이 보드가 그 결정판이다. SoT = design-system track_surface 팔레트 절(코드 배열 = 미러).

기준 — 카테고리 4색 (트랙이 침범하면 안 되는 정보색)

트랙 누적색은 아래 4색의 채도/명도와 구분되는 쿨·중채도여야. 위협 dot·코인이 트랙보다 밝게 떠야 가독 1순위 유지(§9.3).

→ 누적색 전략 = 전부 어둡고 중채도(value↓·sat 중)로 "트랙 = 인프라" 톤. 카테고리는 밝게 떠서 정보로 읽힘.

제안 팔레트 — 쿨 8색 순환 (흰색 고정 + accent)

쿨 아크(azure→cobalt→steel-violet→steel-cyan→teal→jade→sky→ocean) 8색. 전부 카테고리 4색보다 어둡고 채도↓. 각 = 흰색과 짝지어 줄무늬. 스테이지마다 순환(stage idx % 8).

개수 = 8 (스킨 8·변주 다양성 정합 — 9번째 스테이지부터 stage1 색 재순환). 임시 코드값에서 카테고리 근접색 정밀화(periwinkle·violet을 더 어둡게/teal 쪽으로).

★ 충돌 테스트 — 트랙 위에서 dot이 뜨는가 (결정 게이트)

가장 위험한 케이스 = 트랙 누적색이 같은 계열 카테고리 dot을 죽이는 것. 각 accent 줄무늬 위에 🔵🔴🟡🟣 dot을 올려 확인 — dot이 더 밝게 떠야 PASS.

흰 고정 줄 accent 줄(스테이지색) ✅ dot이 줄무늬 위로 뜸 = 채도=정보 유지

스테이지 순환 미리보기 — stage 1 → 8

진행하며 트랙 누적색이 바뀌어 "다른 스테이지" 신호. 흰색·게임 요소는 불변(가독 앵커).
