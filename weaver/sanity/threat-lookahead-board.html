전방 위협 스트립 + 표기 시스템 — dot ⊕ 회피글리프

표기 모델 정정 (2026-06-19 사용자 지적): 위협 응답은 "공격 ⊻ 회피" 이분법이 아니다 — dot(공격)과 회피글리프(↑/↓)는 독립 레이어로, 한 위협에 둘 다 붙을 수 있다. 예: 요격형 낙하물 = 🟡로 쏘거나, 못 쏘고 떨어지면 점프 (spec §6 line 303 "🟡 공중 처치 / 못 잡으면 착지→점프", line 320 가시폭탄 2단계).
스트립 목적 = SwapWindow 보강(§4.7 결정 E, 카메라 단독 1.3~1.9s<2.5s). 배치 = B 하단(확정) · 슬롯 cue = 약한 연동(확정). 토큰 도형 = 레이아웃 placeholder, 실제 = assets/weaver/monster/ 스프라이트.

스트립을 좌→우로 훑으면: 🔴(쏴) · 🟡+↑(쏘거나 점프) · ⚪↓(슬라이드) · 🔵(쏴) · 멀리 가시폭탄 2단계.

dot = 어느 슬롯으로 손이 가고, ↑/↓ = 어느 버튼을 누를지 — 두 채널이 동시에 예고돼 손이 안 꼬인다.

🟡 낙하물처럼 둘 다 붙은 토큰은 "🟡 있으면 쏘고, 없거나 놓치면 점프" = 선택지. 무기 미보유가 하드월이 안 됨(하드월은 베리어 🔵뿐).

슬롯 cue = 약한 연동 — 임박한 🔴 슬롯에 미세 glow 펄스만(자동 플레이감 회피).

결정 = B 하단 (시선→엄지 최단 + 가독 침범 0). A·C = 결정 이력.
🔵 원거리 🔴 근접 🟡 대공 🟣 특수 점프 슬라이드 dot 없음 = 무기 정답 없음
  • 모델 정정 — 어제의 "dot 있음 ⊻ ⚪" 이분법은 낙하물을 못 담았음. 정확한 모델 = dot(공격) ⊕ 회피글리프(↑/↓) 독립 레이어. ⚪는 "글리프만(dot 없음)"의 한 경우. spec 룰 변경 아님(§6 line 303·320에 이미 있음) — 빠진 시각 표기를 채움(디자인 레인).
  • 회피글리프 = 진짜 추가분 — 어제 ⚪는 "피해라"까지만, 점프/슬라이드를 안 알려줬음. ↑/↓ 글리프로 몸 동작까지 대칭 예고(공격은 dot 색으로 슬롯 예고하듯).
  • 둘 다 붙은 토큰(낙하물) = 안전망 — 🟡 미보유·요격 실패해도 점프 생존. 무기 카테고리가 하드월이 되는 건 베리어(🔵 STATIC 게이트, 점프/슬라이드 불가)뿐. 몬스터=충돌 하트(소프트)·낙하물=점프 폴백(소프트).
  • 2단계(가시폭탄) = 시간축 전환 — 공중 🟡 → 착지 🔴/↑. 스트립에선 임박 단계(공중 🟡) 위주 + 미니 전환 표식(→●). 인게임 텔레그래프는 spec대로 단계 전환. 유일한 2단계 위협이라 별도 토큰.
  • 제작 분담 — 디자인 = 토큰 해부·dot/글리프 가독 룰(본 보드) / Unity 절차 = 스폰 큐→토큰 인스턴스화·슬라이드·단계 전환 / 스프라이트 = threat_preview 재사용. 글리프 = `icon_ui` 점프/슬라이드 셰브런 재사용.
  • 확정 후 SoT — design-system threat_lookahead 에 "dot ⊕ 회피글리프" 토큰 해부 추가 + monster-visual-language 표기 룰 정합. spec §6 룰은 이미 존재(변경 X).
